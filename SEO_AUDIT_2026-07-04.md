# SEO Audit: Verotides.com

**Date:** July 4, 2026
**Target:** https://verotides.com
**Context:** Local/regional coastal-conditions dashboard for Vero Beach, FL. Primary goal is organic traffic and local brand visibility.
**Scope:** Technical and on-page SEO, desktop and mobile. Live crawl diagnostic (no GSC access).

---

## Executive Summary

Verotides has a strong baseline architecture (Next.js server-side rendering, fast load speeds, excellent schema markup, and robust sitemaps), but its primary SEO constraint is a **critical crawlability blocker**: the core utility pages (Tides, Weather, Bridges, etc.) are effectively orphaned from the homepage. Search engines cannot follow standard internal links to these pages. 

Additionally, the homepage relies too heavily on stylistic, branded headings ("VEROTIDES.COM", "VERO_CENTRAL_COMMAND") at the expense of clear, keyword-rich signals (e.g., "Vero Beach Coastal Intelligence & Tides") needed to capture local organic search volume.

## Detailed Findings

### 1. Missing Internal Links to Core Utility Pages
* **Category:** Crawlability & Indexation
* **Severity:** Critical
* **Confidence:** High
* **Evidence:** An analysis of the homepage's `href` attributes reveals that while secondary pages like `/guides` and specific articles are linked, the core utility URLs listed in the sitemap (`/tides`, `/fishing`, `/weather`, `/vessels`, `/bridges`) lack standard HTML `<a>` links on the homepage. They only appear within JSON-LD `<script type="application/ld+json">` and Next.js `<script type="speculationrules">`. 
* **Why It Matters:** Search engine crawlers rely on standard `<a>` tags with `href` attributes to discover pages, understand site hierarchy, and distribute link equity. Without these links, the most important utility pages are effectively orphaned from the homepage, drastically reducing their ranking potential.
* **Score Impact:** -25
* **Recommendation:** Implement standard HTML `<a>` tags pointing to the core utility pages (Tides, Weather, etc.) either in the primary navigation header, footer, or as wrappers around the dashboard utility cards.

### 2. Missing Primary Keywords in Homepage H1
* **Category:** On-Page Optimization
* **Severity:** High
* **Confidence:** High
* **Evidence:** The current homepage H1 is `<h1 class="...">VEROTIDES<span class="flicker">.COM</span></h1>`. 
* **Why It Matters:** The H1 tag is one of the strongest on-page relevance signals for search engines. Relying solely on a branded term misses the opportunity to rank for high-intent, non-branded local queries (e.g., "Vero Beach Tides" or "Vero Beach Weather"). 
* **Score Impact:** -10
* **Recommendation:** Update the H1 to incorporate primary descriptive keywords alongside the brand name, or elevate the current descriptive subtitle into the H1. 

### 3. Abstract / Stylistic Heading Structure (H2s)
* **Category:** On-Page Optimization
* **Severity:** Medium
* **Confidence:** High
* **Evidence:** Homepage H2 tags are thematic and stylistic (e.g., `<h2 class="...">VERO_CENTRAL_COMMAND</h2>`) rather than descriptive.
* **Why It Matters:** Search engines use headings (H2-H6) to parse the structure and topical depth of a page. Abstract headings miss opportunities to signal relevance for secondary keywords and clarify content segments for crawlers.
* **Score Impact:** -5
* **Recommendation:** Revise H2 and H3 tags to include descriptive, keyword-relevant terms that clearly label the sections (e.g., "Live Vero Beach Tide Charts", "Local Weather & Storm Sentry"). 

### 4. Viewport Scalability Disabled (Mobile Accessibility)
* **Category:** Technical Foundations
* **Severity:** Medium
* **Confidence:** High
* **Evidence:** The meta viewport tag is set to: `<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover"/>`.
* **Why It Matters:** `user-scalable=no` and `maximum-scale=1` prevent users from zooming in on mobile devices. This violates WCAG accessibility guidelines and creates a poor user experience, which is a negative signal for Google's mobile-first indexing.
* **Score Impact:** -5
* **Recommendation:** Remove `user-scalable=no` and `maximum-scale=1` from the viewport meta tag to allow native browser pinch-to-zoom functionality.

## Drafted Fix — Critical Blocker (Orphaned Utility Pages)

**Root cause (verified in source):** `app/layout.tsx` references the utility pages only in `SiteNavigationElement` JSON-LD (lines 190–201) and the `speculationrules` script (lines 203–206). Neither is a crawlable `<a href>`. There is no `<nav>`/`<header>` with links in the layout, and `app/page.tsx` links only to `/guides`. Result: `/tides`, `/fishing`, `/weather`, `/vessels`, `/bridges`, `/spoil-islands` are orphaned from the homepage.

**Fix:** `app/page.tsx` is a Server Component, so this nav renders into the initial HTML (crawlable). Insert immediately after the `</header>` (line 41), before `<DashboardShell />`. Keyword-rich anchor text also partially addresses Finding #2.

```tsx
{/* Primary site navigation — crawlable internal links to core utility pages (SEO: fixes orphaned pages) */}
<nav aria-label="Primary" className="w-full border-b-2 border-primary/30 bg-black">
  <ul className="max-w-7xl mx-auto flex flex-wrap gap-x-1 gap-y-2 px-4 md:px-8 py-3 font-mono text-xs md:text-sm uppercase tracking-wider">
    {[
      { href: '/tides', label: 'Vero Beach Tides' },
      { href: '/fishing', label: 'Fishing & Bite Times' },
      { href: '/weather', label: 'Beach Conditions' },
      { href: '/vessels', label: 'Vessel Tracker' },
      { href: '/bridges', label: 'Bridge Status' },
      { href: '/spoil-islands', label: 'Spoil Islands' },
    ].map(({ href, label }) => (
      <li key={href}>
        <Link
          href={href}
          className="block px-3 md:px-4 py-2 text-primary/80 hover:text-black hover:bg-primary border border-transparent hover:border-primary transition-colors duration-200 whitespace-nowrap"
        >
          {label}
        </Link>
      </li>
    ))}
  </ul>
</nav>
```

`Link` is already imported in `page.tsx` (line 2) — no new import needed.

**Site-wide upgrade (recommended follow-up):** extract the block to `src/components/verotide/SiteNav.tsx` and render it in `app/layout.tsx` `<body>` just before `{children}`, so *every* page (not just the homepage) carries crawlable sibling links. That also gives the utility sub-pages internal links back to each other, spreading link equity across the whole cluster.
